# 项目协作群与测试员工

协作群入口位于工作台的全局导航。使用顶栏切换项目，从左侧列表选择群。「提到我」可以打开提及原文。群成员来自项目成员名单，项目的只读成员可以查看讨论。群消息和提醒保存在 LoopForge 中。

平台管理员和项目 Owner 可以在「设置 → 项目配置 → 项目成员」创建测试员工。创建后，员工使用正式账号登录。系统通过该账号发出的自动回复与人工消息使用同一个用户 ID。项目配置中的「管理自动参与」可编辑员工、暂停与恢复参与，也能查看失败记录。员工本人登录后在协作群的「成员与设置」可以暂停自己的自动参与。

## 模型与测试群

可以在员工管理中授权当前账号个人配置里的 API 模型连接，也可以为单个员工配置专用连接。支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。授权共享时要选择可用模型。源连接变更地址、协议或撤销授权后，员工管理者需要选择有效的新连接。专用连接在服务端加密存储。

项目 Owner 或平台管理员在「成员与设置」逐群开启自动讨论。启用的群会把本群近期文本发送给配置的模型。人工消息开启一轮，点名优先，其他员工也可回复或保持沉默。默认每轮连续自动回复上限为四条。关闭群自动讨论后，正式员工账号依然可以由人操作。

## 从官方 0.4.2 升级

1. 在构建机从本分支构建自定义版本镜像。保留当前官方镜像的版本和镜像摘要。先用隔离的 MySQL 数据副本验证升级。
2. 备份现有 MySQL 数据以及部署配置。在目标数据库执行 `migrations/042_project_employee_discussions.sql`。该迁移新增配置、提及和队列表。升级过程保留账户、项目成员和聊天记录。
3. 如需专用连接，在部署配置中生成并留存 `AGENTFLOW_EMPLOYEE_CREDENTIAL_KEY`。值为随机的 32 字节密钥的 Base64 表示。备份时保留该密钥，恢复时使用同一值。
4. 服务端默认通过 HTTPS 访问公开模型 API。平台管理员或项目 Owner 管理的连接，会在调用时自动放行该连接配置的精确 IP 与端口；普通成员授权的源连接仍需在 `AGENTFLOW_EMPLOYEE_MODEL_ALLOW_ADDRS` 中声明实际的可信 IP 与端口（逗号分隔）。验证平台容器可以通过该地址访问模型，再从员工管理页测试连接。
5. 通过 `LOOPFORGE_IMAGE` 启动自定义镜像。先用两个正式账号确认群聊天、提及与历史消息，再在一个测试群启用自动讨论并验证真实模型接管。

整体替换既有项目成员的 API 调用方先读取项目，把返回的 `membersVersion` 随 `members` 提交。只改其他项目设置时省略这两个字段。

如需回退，先关闭已启用的群自动讨论。停止自定义镜像并恢复官方镜像及其启动配置。新增表可留在数据库中供再次升级时使用。先在副本演练回退，再操作运行环境。
